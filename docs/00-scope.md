# 00 · 定位与边界

## 一句话

> Dual6 是 `(bit, trit)` 的联合存储容器，不是计算进制。

## 命名

中文名**二生三**（取自《道德经》"道生一，一生二，二生三，三生万物"）。

**用本编码存放的模型是一个 `.p6` 文件**（例如 `model.p6`）。后缀取 `6`，
因为 6 是第一个完全数（1 + 2 + 3 = 6），也是这个编码的起源——
2 态 × 3 态 = 6 态。容器只规定后缀与帧格式，不规定文件里放什么。

## 核心边界：承载，不解释

容器层只保证**原样、可校验地搬运**，不解释载荷的数值语义。判断一项功能
是否属于本工具，看它是"搬运/标注"还是"运算/解释"：

| 能力 | 归属 |
|---|---|
| 位序 / 端序 / 宽度 / 布局 / 块 / 帧 / CRC | 容器层 |
| element type / shape / strides 等**元数据标签** | 容器层（只贴标签，不做运算） |
| 浮点 / 定点 / 三值的算术与反量化 | 引擎层 |
| matmul / 广播 / 转置等张量运算 | 算子层 |
| attention / 路由 / 激活等推理语义 | 推理运行时 |

## 交换模型

二进制引擎和三进制引擎各自用自己的算术计算；Dual6 只负责把**同一个值**
存成两个视图，让两边读取时都不需要跨进制转换。

- 写：一次（调用方只给一个表示；编码器把它压成一串码元，每个码元同时带 bit 和 trit 两个分量）；
- 读：各读各的，零转换、无损；
- 容器不做 `+ - * /`；算术在两端引擎里。

如果只想让两边各自读写自己的数据（不要求"同一个值"），那是
**independent-dual** 模式：各填各的通道，另一边读到的是默认值。

## 做什么（容器层）

- 单符号 mux / demux；
- 序列打包 / 解包；
- 交错布局、双平面布局、固定块；
- 位序、端序、宽度、错误码；
- 让二进制引擎和三进制引擎共享同一块物理存储；
- 帧头携带 dtype 等**类型标签**（已实现：D6P2 的 raw / binary / ternary / mixed）；
- 承载任意 dtype 的原始字节载荷（opaque payload），但不解释其数值含义。

## 不做什么（不解释）

- 不定义 `d` 上的加减乘除；
- 不定义普通 base-6 算术；
- 不做二进制 / 三进制数值翻译；
- 不实现浮点 / 定点 / 三值的算术与反量化；
- 不解释张量的计算语义（广播、转置、matmul 等）；
- 不做推理语义（attention、路由、激活函数等）；
- 不做外部系统连接，也不做模型 / 量化格式连接（例如 GGUF / GGML block 适配）；
- 不实现任何推理、量化或模型运行时逻辑。

> 注意：**张量元数据**（element type / shape / strides）是容器层的合法内容；
> 把"支持张量"理解成"容器要算张量"是越界。当前 D6P2 只带 dtype；
> 张量帧（dtype/shape 元数据）只是提案，未实现，不进入 v0.3 API。
>
> 可选编解码层：`dual6.exact_dual` 实现"同一个数 N 的 base-2 / balanced-3
> 双展开、双视图无损读取"。它是容器之上的 codec，核心容器仍不做数值翻译；
> 见 `docs/11-exact-dual.md`。
>
> 可选算术层：`dual6.arithmetic` 对 exact-dual 序列提供 `+ - * divmod`，
> 操作对象是解码后的整数，不是码元 `d` 本身；见 `docs/12-arithmetic.md`。

## 分层

```text
下游（范围外）：数值桥 / 量化格式 / 模型格式 / 推理运行时
────────────────────────────────────────
适配层：二进制引擎 / 三进制引擎（单通道桥接）
────────────────────────────────────────
容器层：码元 / 序列 / 布局 / 块 / 帧（可带 dtype 标签）
```

容器层只负责运输，加工交给两边引擎。本版本只交付容器层及其自带的二进制 /
三进制单通道桥接；其余外部连接由下游项目在冻结的 core API 之上自行构建。
